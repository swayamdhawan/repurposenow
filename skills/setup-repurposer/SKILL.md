# RepurposeNow Setup

Configure the RepurposeNow plugin by selecting an output destination, source folder, and default formats to generate. This saves a `repurposer-config.md` file that all format skills read automatically. Run this once when getting started, or revisit it any time you want to change where content is delivered or which formats are generated by default.

## Capabilities

- Check for an existing `repurposer-config.md` and offer to update specific settings or start fresh
- Guide selection of output destination: local folder, Notion, or Google Drive
- Detect whether required connectors are available for Notion or Google Drive; offer local folder fallback if not
- Capture destination details (folder path, Notion URL, or Drive folder name)
- Set the source folder where raw content is dropped before repurposing
- Choose which of the 6 formats are generated by default when running `/repurpose-all`
- Save the completed configuration to `repurposer-config.md`

## How to Use

Invoke this skill at any point to create or update the repurposer configuration:

- `Set up the content repurposer`
- `Configure where my content gets saved`
- `Change my output destination`
- `Update my default formats`
- `/setup-repurposer`

## Input Parameters

| Parameter | Required | Description |
|-----------|----------|-------------|
| Output destination | No | Where to deliver repurposed content: local folder, Notion, or Google Drive (prompted during setup) |
| Destination details | No | Folder path, Notion page/database URL, or Drive folder name (prompted based on destination choice) |
| Source folder path | No | Where source content files are dropped before repurposing (defaults to `./sources/`) |
| Default formats | No | Which of the 6 formats to generate when running `/repurpose-all` (defaults to all 6) |

## Output

A `repurposer-config.md` file saved to the project folder, containing:
- Output destination type and path or URL
- Source folder path
- Default formats enabled for `/repurpose-all`

## Phase 1: Check for Existing Config

Before asking any questions, look for an existing `repurposer-config.md` in the project folder.

### If no config exists:

Greet the user and explain what's about to happen:

> "I don't see a repurposer config yet. I'll walk you through a few quick choices — where to deliver your content, where you'll drop source files, and which formats to generate by default. It only takes a minute."

Proceed to Phase 2.

### If a config already exists:

Read the existing `repurposer-config.md` and summarize what it currently contains. Then offer two options:

> "I found your existing repurposer config. Here's what it's set to: [brief summary of destination type, path, source folder, and enabled formats]. Would you like to:
>
> 1. **Update specific settings** — tell me what you want to change and I'll revise just those parts
> 2. **Start fresh** — go through the full setup again from the beginning"

Wait for the user's choice before proceeding.

- If updating specific settings: ask only about the settings being changed, then skip to Phase 6 with the existing config as the base.
- If starting fresh: proceed to Phase 2 with the full setup flow.

---

## Phase 2: Output Destination

Ask the user where they want repurposed content delivered:

> "Where should I deliver your repurposed content?
>
> **A) Local folder** — saves files to a folder on your computer (works for everyone, no setup required)
> **B) Notion** — saves to a Notion page or database (requires the `document storage` connector)
> **C) Google Drive** — saves to a Google Drive folder (requires the `document storage` connector)
>
> Which would you like to use?"

Wait for the user's response.

### If A (Local folder):
Proceed to Phase 3A.

### If B (Notion):
Check whether the Notion connector (`~~document storage`) is available.
- If available: proceed to Phase 3B.
- If unavailable: explain and offer fallback:

> "It looks like the Notion connector isn't connected yet. To use Notion, you'd need to add the `document storage` connector in your Claude settings and authorize it with your Notion workspace.
>
> Would you like to fall back to a local folder for now, or pause setup until the connector is added?"

Wait for the user's response. If they choose local folder, proceed to Phase 3A. If they want to pause, stop and let them know to re-run `/setup-repurposer` after adding the connector.

### If C (Google Drive):
Check whether the Google Drive connector (`~~document storage`) is available.
- If available: proceed to Phase 3C.
- If unavailable: explain and offer fallback:

> "It looks like the Google Drive connector isn't connected yet. To use Google Drive, you'd need to add the `document storage` connector in your Claude settings and authorize it with your Google account.
>
> Would you like to fall back to a local folder for now, or pause setup until the connector is added?"

Wait for the user's response. If they choose local folder, proceed to Phase 3A. If they want to pause, stop and let them know to re-run `/setup-repurposer` after adding the connector.

---

## Phase 3: Destination Details

Collect the specific destination details based on the choice made in Phase 2.

### Phase 3A: Local Folder

> "What folder path should I save content to? You can enter an absolute path (e.g., `/Users/yourname/Content/repurposed`) or a relative path from your project folder.
>
> Press Enter to use the default: `./output/`"

If the user provides a path, record it. If they press Enter or say nothing, use `./output/`.

### Phase 3B: Notion

> "Paste the URL of the Notion page or database where you'd like content saved. This should be a page you own and can write to."

Wait for the user to paste the URL. Record it as-is.

### Phase 3C: Google Drive

> "What's the name or path of the Google Drive folder where you'd like content saved? For example: `Content/Repurposed` or just `Repurposed Content`."

Wait for the user to provide the folder name or path. Record it.

---

## Phase 4: Source Folder

Ask where the user will drop source content files before repurposing:

> "Where will you drop the source content you want repurposed — things like transcripts, notes, or draft posts?
>
> Press Enter to use the default: `./sources/`"

If the user provides a path, record it. If they press Enter or say nothing, use `./sources/`.

---

## Phase 5: Default Formats

Ask which formats should be generated automatically when running `/repurpose-all`:

> "Which formats should I generate by default when you run `/repurpose-all`? All 6 are selected by default — let me know if you want to turn any off.
>
> - [x] LinkedIn post
> - [x] Twitter/X thread
> - [x] Email newsletter section
> - [x] Blog post
> - [x] Short-form video script (Shorts/Reels/TikTok)
> - [x] Carousel slides
>
> Reply with any formats you'd like to disable, or say 'all' to keep the full set."

Wait for the user's response. Record which formats are enabled based on their answer.

---

## Phase 6: Save repurposer-config.md

Save the completed configuration as `repurposer-config.md` in the project folder using the following exact template:

```markdown
---
name: Content Repurposer Configuration
created: [YYYY-MM-DD]
updated: [YYYY-MM-DD]
first_run_complete: false
---

## Output Destination
- Type: [local | notion | gdrive]
- Path: [folder path, Notion page URL, or Drive folder]

## Source Folder
- Path: [folder path]

## Default Formats
- [x] LinkedIn
- [x] Twitter
- [x] Email
- [x] Blog
- [x] Shorts
- [x] Carousel
```

Replace checkboxes with `[ ]` for any formats the user chose to disable.

Use today's date for both `created` and `updated` on first creation. On subsequent updates, preserve the original `created` date and update only the `updated` date. Leave `first_run_complete: false` — format skills update this flag after the first successful run.

After saving, confirm with the user:

> "Your repurposer config is saved. Here's the summary:
>
> **Output:** [destination type] → [path or URL]
> **Source folder:** [path]
> **Default formats:** [list of enabled formats]
>
> You're ready to go. Drop a file in your source folder and run `/repurpose-all` to generate content, or use individual format skills like `/repurpose-linkedin` to generate one format at a time."

---

## Re-run Behavior

If `repurposer-config.md` already exists (covered in Phase 1), always offer to update specific settings rather than forcing a full restart. Preserve existing values for any settings not being updated. Never overwrite the full file without explicit user confirmation.

---

## Best Practices

1. **Default to local folder** — it works for everyone without any connector setup; only prompt for Notion or Google Drive details if the user explicitly selects them
2. **Connector check before asking for details** — always verify connector availability before asking for a Notion URL or Drive folder name; don't collect details you can't use
3. **Respect the defaults** — most users won't need to change source folder or output path; make it easy to accept defaults with a single keypress
4. **Preserve first_run_complete** — never reset this flag to `false` on updates; it's managed by format skills, not by this setup skill
5. **Keep the format list in sync** — the 6 format names in the config (LinkedIn, Twitter, Email, Blog, Shorts, Carousel) must match exactly what format skills check for; do not rename or reorder them

## Limitations

- Connector availability for Notion and Google Drive depends on what the user has authorized in their Claude environment; this skill cannot add connectors on their behalf
- The `./output/` and `./sources/` defaults are relative to the working directory at the time format skills run; users working across multiple project folders may need to use absolute paths
- The `first_run_complete` flag is informational only; it tracks whether the post-first-run "what else you can do" message has been shown, and is updated by format skills, not by this skill
